# 03. 배경 이미지 최적화

> 작업일 2026-09-02 · 기준값 [01-baseline.md](./01-baseline.md)

## 문제

코드 스플리팅 이후 초기 로드에서 가장 큰 것이 JS가 아니라 배경 이미지였다.

| 파일 | 크기 | 원본 해상도 | 표시 크기 | 배율 |
| --- | --- | --- | --- | --- |
| `bg-stripe.png` | 552.90 kB | 1812 x 2456 | 약 393 x 614 | **약 4.6x** |
| `home-gradient-top.png` | 366.33 kB | 1300 x 1300 | 650 x 650 | 2x |
| `home-gradient-bottom.png` | 332.29 kB | 1300 x 1300 | 650 x 650 | 2x |
| **합계** | **1,251.52 kB** | | | |

같은 시점의 초기 로드 JS가 810 kB였으므로 **이미지 3장이 JS보다 컸다.**

## 이미지마다 다른 방법을 썼다

셋 다 CSS로 바꾸거나 셋 다 WebP로 바꾸는 대신, 성격에 따라 나눴다.

| 이미지 | 방법 | 판단 근거 |
| --- | --- | --- |
| `bg-stripe` | **WebP 변환** | 폭이 제각각인 세로 밴드 + 하단 글로우가 겹친 텍스처. CSS로 재현하면 디자인이 달라진다 |
| `home-gradient-top` | **CSS radial-gradient** | 단순한 방사형 글로우. 알파 채널 탓에 WebP로도 52 kB가 남는다 |
| `home-gradient-bottom` | **CSS radial-gradient** | 동일 |

---

## bg-stripe — WebP 변환

원본이 표시 크기의 약 4.6배였다. 3배 해상도인 1200px 로 줄이고 WebP로 인코딩했다.

```js
await sharp(png).resize({ width: 1200 }).webp({ quality: 80 }).toBuffer();
```

| | 크기 |
| --- | --- |
| 이전 (PNG 1812x2456) | 552.90 kB |
| 이후 (WebP 1200x1626) | **13.72 kB** |
| 감소 | **-97.5%** |

내용이 흐릿한 그라데이션 텍스처라 해상도를 낮춰도 확대 시 차이가 드러나지 않는다.
디자인은 원본 그대로 유지된다.

사용처 3곳(`IntroStep`, `OnboardingBackground`, `SplashStep`)의 import 경로만 바꿨다.

## 그라데이션 2장 — CSS 대체

### 값은 원본에서 뽑았다

눈대중이 아니라 원본 PNG의 픽셀을 중심에서 바깥으로 샘플링해 분포를 확인했다.

**home-gradient-top** (중심 → 우측)

| 반지름 | RGBA | 알파 |
| --- | --- | --- |
| 0% | rgba(235,240,255) | 0.659 |
| 30% | rgba(235,239,255) | 0.690 |
| 50% | rgba(231,237,255) | 0.714 |
| 60% | rgba(232,238,255) | 0.643 |
| 70% | rgba(232,239,255) | **0.306** |
| 80% | rgba(223,223,255) | 0.031 |
| 90% | — | 0 |

중심부 알파가 평평하게 유지되다가 **반지름 70% 지점부터 급격히 사라지는** 분포다.
그대로 옮겼다.

```ts
export const HOME_GRADIENT_TOP =
  "radial-gradient(circle at 50% 45%, " +
  "rgba(233,238,255,0.72) 0%, " +
  "rgba(233,238,255,0.70) 55%, " +
  "rgba(233,238,255,0.30) 70%, " +
  "rgba(233,238,255,0) 88%)";
```

`home-gradient-bottom` 도 같은 방식으로 도출했다 (중심 알파 0.59, 70%에서 0.22).

### 근사 오차를 측정했다

CSS 그라데이션과 동등한 SVG를 만들어 원본과 픽셀 단위로 비교했다.

**원본 대비 직접 비교**

| | top | bottom |
| --- | --- | --- |
| 알파 평균 오차 | 14.16 / 255 (5.6%) | 14.11 / 255 (5.5%) |
| 알파 최대 오차 | 62 / 255 (24.3%) | 75 / 255 (29.4%) |
| 색상 평균 오차 | 2.88 / 255 | 3.36 / 255 |

알파 최대 오차만 보면 24~29%로 커 보인다.
하지만 이 글로우는 **배경색 `#FDFBFF` 위에 얹히는 장식**이므로, 합성 후 값이 실제로 보이는 차이다.

**배경 합성 후 비교**

| | top | bottom |
| --- | --- | --- |
| 평균 색차 | **1.31 / 255 (0.5%)** | **0.87 / 255 (0.3%)** |
| 최대 색차 | 8.3 / 255 (3.3%) | 6.5 / 255 (2.6%) |

평균 1 내외로 육안 식별이 어려운 수준이다.
이 측정이 없었다면 알파 오차 29%만 보고 포기했을 것이다.

### 구현

값을 `src/constants/backdropGradient.ts` 로 분리했다.
`HomeBackdrop` 과 `emergency-report` 두 곳에서 같은 그라데이션을 쓰기 때문이다.

`HomeBackdrop` 은 SVG 글로우와 그라데이션을 같은 배열로 관리하고 있어,
`src` 가 있으면 `<img>`, `background` 가 있으면 `<div>` 로 그리도록 했다.
Figma 레이어 순서와 좌표 계산은 그대로 유지된다.

## 결과

| 항목 | 이전 | 이후 | 변화 |
| --- | --- | --- | --- |
| `bg-stripe` | 552.90 kB | 13.72 kB | -97.5% |
| `home-gradient-top` | 366.33 kB | **0 kB** | CSS 대체 |
| `home-gradient-bottom` | 332.29 kB | **0 kB** | CSS 대체 |
| **합계** | **1,251.52 kB** | **13.72 kB** | **-98.9%** |

초기 로드 JS는 810.26 → 810.60 kB 로 0.34 kB 늘었다. 그라데이션 문자열이 번들에 들어간 몫이다.
1,238 kB 를 줄이고 0.34 kB 를 추가했다.

PWA 프리캐시는 868.68 → 869.01 KiB 로 사실상 동일하다.
PNG들은 원래 프리캐시 대상이 아니라 필요한 화면에서 개별 로드되던 자산이었다.
즉 **온보딩·홈 화면 진입 시 받던 1.25 MB 가 사라졌다.**

## 재현

변환은 `sharp` 로 일회성 실행했고 결과물만 커밋했다.
다시 필요하면 `npm i -D sharp` 후 아래를 실행한다.

```js
// bg-stripe
await sharp(readFileSync("bg-stripe.png"))
  .resize({ width: 1200 })
  .webp({ quality: 80 })
  .toBuffer();
```

그라데이션 값을 다시 뽑으려면 원본 PNG가 필요한데 삭제했으므로,
Git 히스토리에서 복원해야 한다.

```bash
git show a2bea26:src/assets/shared/home-gradient-top.png > /tmp/top.png
```
