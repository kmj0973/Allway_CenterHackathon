# 04. Lighthouse 재측정 — 실제 개선 효과

> 측정일 2026-09-02 · 기준 커밋 `e92cff3` vs 현재 `28e69ee`

지금까지의 최적화([02](./02-icon-optimization.md), [03-code-splitting](./03-code-splitting.md),
[03-background](./04-background-images.md))가 실제 로딩 속도를 얼마나 바꿨는지 측정했다.

번들 크기는 결정론적이라 바로 근거가 되지만, **LCP 같은 실측 지표는 편차가 크다.**
[02](./02-icon-optimization.md)에서 동일 빌드 3회 측정에 Performance 35~44 편차가 나온 뒤
"Lighthouse 점수를 근거로 쓰지 않는다"는 방침을 세웠다. 이번에는 그 방침대로 측정 방법을 갖춰 다시 쟀다.

---

## 측정 방법

| 항목 | 값 |
| --- | --- |
| 도구 | Lighthouse 13.4.1 (headless Chrome) |
| 디바이스 | 모바일 에뮬레이션 |
| 스로틀링 | `simulate` · 1,474 Kbps · RTT 150 ms · CPU 4배 감속 |
| 대상 | `vite preview` 로 서빙한 프로덕션 빌드, 경로 `/` |
| 반복 | **각 빌드 5회, 중앙값 사용** |

### 기준 빌드를 재현하는 방법

기준값 문서([01](./01-baseline.md))의 수치는 **1회 측정**이라 그대로 비교할 수 없었다.
같은 조건에서 다시 재기 위해 기준 커밋을 별도 워크트리에 체크아웃해 빌드했다.

```bash
git worktree add ../baseline e92cff3
cd ../baseline && npm ci && npm run build && npx vite preview
```

빌드 산출물이 `index-SgkY3pRU.js  2,375.86 kB` 로 문서의 기준값과 정확히 일치하는 것을 확인했다.

## LCP 에는 바닥이 있다

`SplashStep` 에 스플래시 최소 노출 시간이 정의돼 있다.

```ts
// 스플래시가 노출되는 최소 시간(ms)
const SPLASH_DURATION = 4000;
```

**LCP 는 이 4초 아래로 내려갈 수 없다.** 현재 LCP 4,565 ms 중 약 4,000 ms 가 이 타이머다.

로딩에 해당하는 부분만 떼어 보면 대략 이렇다.

```
기준값  6,929 - 4,000 = 2,929 ms
현재    4,565 - 4,000 =   565 ms
```

정확한 분해는 아니다(스플래시는 FCP 이후 시작된다). 그래도 **남은 LCP 의 대부분이
네트워크나 번들이 아니라 의도된 애니메이션 시간**이라는 점은 분명하다.

성능 지표를 더 끌어올리려면 스플래시 시간 조정이 가장 큰 항목이다.
다만 이는 성능 문제가 아니라 **기획·디자인 결정**이므로 팀과 상의할 사안이다.

## 측정 과정에서 틀린 두 가지

### 1. 기준값을 1회 측정으로 잡았다

[01-baseline.md](./01-baseline.md) 의 Performance 52, LCP 9.4 s 는 단일 측정이었다.
5회 재측정한 중앙값은 **Performance 56, LCP 6,929 ms** 로 달랐다.

기준값이 부정확하면 개선폭도 부정확해진다.
`01` 문서에는 이미 신뢰도 주의를 덧붙여 두었고, 이 문서의 수치를 정본으로 삼는다.

### 2. 엉뚱한 서버를 측정했다

기준 빌드를 포트 4174 로 띄우려 했는데 **그 포트가 이미 사용 중이라 Vite 가 4177 로 옮겨 붙였다.**
그것을 모르고 4174 를 측정했고, 그 포트는 이전에 띄워 둔 현재 빌드 서버였다.

그 결과 "기준값과 현재가 동일하다"는 잘못된 결론을 냈다.
Lighthouse 리포트에 찍힌 **번들 해시가 양쪽 모두 `index-BzdIprgh.js`** 인 것을 보고 발견했다.

> **교훈**: 측정 전에 대상이 맞는지 확인하는 절차가 필요하다.
> 이 프로젝트에서는 **빌드 해시**가 그 역할을 한다.
>
> ```bash
> curl -s http://localhost:PORT/ | grep -o 'index-[A-Za-z0-9_-]*\.js'
> ```

## 재현

```bash
# 현재 빌드
npm run build && npx vite preview --port 4173

# 기준 빌드
git worktree add ../baseline e92cff3
cd ../baseline && npm ci && npm run build && npx vite preview --port 4177

# 측정 대상 확인 (반드시)
curl -s http://localhost:4173/ | grep -o 'index-[A-Za-z0-9_-]*\.js'
curl -s http://localhost:4177/ | grep -o 'index-[A-Za-z0-9_-]*\.js'

# 각 5회 측정 후 중앙값
npx lighthouse http://localhost:4173/ --output=json --output-path=./run1.json \
  --chrome-flags="--headless=new" --only-categories=performance --quiet
```
